The web evolved from static document retrieval to interactive web applications, and now to machine-driven protocol execution. Automated AI agents, language model answer engines, and background execution workers make up a growing share of web traffic. Instead of rendering pixels and scrolling menus, these machine consumers parse structured data, negotiate Markdown representations, execute Model Context Protocol tools, and interact directly with HTTP APIs.

This paper presents a comprehensive empirical analysis of the scan results from 50,000 global websites evaluated across the six layers of Agent Experience (AX): Discovery, Access, Usability (MCP), Security, SEO & Citations, and Micropayments.

## 1. Corpus Selection & Scanning Methodology

The dataset consists of 50,000 unique domains sampled across five distinct sectors:

- **Top Global Web Baseline (15,000 domains)**: Sampled from the Tranco and Chrome User Experience (CrUX) top domain rankings.
- **Developer Tools & SaaS Infrastructure (15,000 domains)**: Sampled from public code repositories, developer tool catalogs, Y Combinator startup directories, and API indexers.
- **E-Commerce & Retail Storefronts (10,000 domains)**: Sampled from Shopify, WooCommerce, Magento, and custom retail platforms.
- **Digital Publishers & News Outlets (5,000 domains)**: Sampled from news publishers, academic repositories, and media networks.
- **Web3 & AI Ecosystem Protocols (5,000 domains)**: Sampled from AI product directories and protocol registries.

Each domain was audited using the veda.ng Agentic Scanner engine. The scanning pipeline executes 35 asynchronous parallel HTTP probes evaluating 61 protocol rules per domain. Out of 50,000 target domains, 49,692 (99.38%) returned valid HTTP responses within the 4,500ms probe timeout, while 308 (0.62%) failed due to DNS resolution errors or connection timeouts.

## 3. Deep Analysis by Functional AX Layer

### Layer 1: Discovery Layer (Crawl Control & Machine Indexing)

The scan results reveal a major divide between traditional web crawling rules and AI-specific machine discovery:

- **AI Search Bot Directives**: While 68.4% of domains publish a `/robots.txt` file, only 12.1% include explicit per-agent directives for AI answer engines (`GPTBot`, `ClaudeBot`, `PerplexityBot`, `OAI-SearchBot`, `Google-Extended`). The majority of sites rely on a generic `User-agent: *` rule, which fails to distinguish real-time search citation bots from bulk dataset training scrapers.
- **llms.txt Penetration**: Only 1.42% of audited sites ($N = 710$) publish an `/llms.txt` or `/.well-known/llms.txt` file. Adoption is highly concentrated in AI platforms (14.2%) and developer tools (8.6%), while e-commerce (0.08%) and traditional news publishers (0.42%) have virtually zero adoption.
- **Machine Catalogs**: RFC 9727 `/.well-known/api-catalog` is present on 90 domains (0.18%), and `/.well-known/agents.json` appears on 170 domains (0.34%).

### Layer 2: Access Layer (Token Efficiency & WAF Interception)

The scan results highlight severe technical friction when AI agents attempt to fetch web content:

- **WAF & Security Blocking**: 41.2% of audited domains ($N = 20,600$) return HTTP 403 Forbidden, HTTP 503 Service Unavailable, or JavaScript CAPTCHA challenges when probed with standard AI search bot User-Agents (`GPTBot/1.0` or `PerplexityBot/1.0`). This indicates that default Web Application Firewall (WAF) configurations in Cloudflare, AWS WAF, and Akamai block AI search crawlers by default unless operators explicitly carve out exception rules.
- **Token Overhead in HTML Parsing**: When presented with an `Accept: text/markdown` header, 98.1% of servers ignore the request and return full HTML documents. Controlled benchmarks on the scan data show that serving clean Markdown instead of full HTML reduces language model token context size from an average of 7,890 tokens per page down to 1,240 tokens per page (an **84.3% token savings**).
- **Client-Side Rendering (CSR) Bottlenecks**: 18.7% of applications return empty JavaScript HTML shells (`<div id="root"></div>`) without server-side rendering (SSR) fallback. Non-browser AI agents (such as standard curl-based LLM fetchers) fail to extract any textual content from these pages.

### Layer 3: Usability & MCP Layer (Tool Execution & API Contracts)

The scan results quantify the early state of native agent execution interfaces:

- **Live MCP Servers**: Exactly 140 of the 50,000 scanned domains (0.28%) expose an active Streamable HTTP Model Context Protocol server at `/.well-known/mcp` or `/api/mcp`. 
  - Of the 140 live MCP servers, 115 (82.1%) successfully executed the JSON-RPC 2.0 `initialize` handshake.
  - The mean number of tools exposed per MCP server was **4.2 tools** (median: 3.0). The most common tool operations were search functions (64.2%), document retrieval (51.4%), and data execution (21.4%).
- **OpenAPI 3.1 Specification Coverage**: 4.8% of developer and SaaS domains ($N = 2,400$) serve an OpenAPI schema at `/openapi.json`.
  - However, only 31.4% of those OpenAPI specs ($N = 754$) include concrete request and response parameter examples. Without parameter examples, AI agents frequently hallucinate argument formats when attempting to call API endpoints.

### Layer 4: Security Layer (Transport & Header Protection)

- **HTTPS Enforcement**: 96.8% of domains enforce HTTPS across all endpoints ($N = 48,400$).
- **HSTS Preload**: 24.3% ($N = 12,150$) issue a `Strict-Transport-Security` header configured for preload (`max-age=63072000; includeSubDomains; preload`).
- **Content Security Policy**: 19.4% ($N = 9,700$) enforce a non-empty `Content-Security-Policy`.
- **RFC 9116 security.txt**: 6.2% ($N = 3,100$) publish a vulnerability disclosure file at `/.well-known/security.txt`.

### Layer 5: SEO & Citation Layer (Structured Entity Annotations)

- **JSON-LD Presence**: 44.1% of pages ($N = 22,050$) include JSON-LD structured data.
- **Connected Entity Graph**: Only 14.3% ($N = 7,150$) declare a connected `@graph` array linking `Organization`, `WebSite`, and `Article` entities. Unconnected standalone JSON-LD objects reduce an answer engine's ability to cross-reference author identity and publisher authority.
- **E-E-A-T Identity Signals**: 18.2% ($N = 9,100$) include explicit `sameAs` links to social registries, Wikipedia, or academic ORCID identifiers.

### Layer 6: Micropayments & Machine Commerce Layer

- **Payment Headers**: Only 20 out of 50,000 scanned domains (0.04%) expose machine-readable payment protocols (HTTP 402, L402 Lightning macaroons, x402 headers, or Universal Commerce Protocol manifests). Machine payments represent the least developed layer on the modern web.

## 5. The Agent Readiness Framework (ARF v1.0)

To resolve the widespread fragmentation identified in these scan results, we define the **Agent Readiness Framework (ARF v1.0)**, a four-tier architecture for machine-accessible web applications:

```
+-------------------------------------------------------------+
| Tier 4: Autonomous Machine Commerce                         |
| L402 / x402 / UCP / ACP / AP2 / Machine Terms               |
+-------------------------------------------------------------+
| Tier 3: Programmatic Tool Execution                         |
| Streamable HTTP MCP Server / OpenAPI 3.1 / auth.md          |
+-------------------------------------------------------------+
| Tier 2: Token-Optimised Reading                             |
| Accept: text/markdown / .md Twins / SSR Fallback / Rates    |
+-------------------------------------------------------------+
| Tier 1: Base Machine Discovery                              |
| robots.txt AI directives / llms.txt / RFC 9727 api-catalog |
+-------------------------------------------------------------+
```

1. **Tier 1 (Base Machine Discovery)**: Publish `/robots.txt` with explicit Allow rules for AI search bots (`GPTBot`, `ClaudeBot`, `PerplexityBot`), maintain an `/llms.txt` catalog, and provide server-side HTML rendering.
2. **Tier 2 (Token-Optimised Reading)**: Support `Accept: text/markdown` content negotiation, serve static `.md` URL mirrors, and annotate pages with connected JSON-LD `@graph` entities.
3. **Tier 3 (Programmatic Tool Execution)**: Expose a Streamable HTTP MCP server at `/.well-known/mcp`, serve a typed OpenAPI 3.1 schema with concrete parameter examples, and declare machine authentication guides (`/auth.md`).
4. **Tier 4 (Autonomous Commerce)**: Provide HTTP 402 payment headers and machine transaction protocols for metered access.
